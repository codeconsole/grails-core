The Grails Quartz plugin allows your application to schedule jobs to be executed on a fixed interval or according to a cron expression. Scheduling is backed by the https://www.quartz-scheduler.org/[Quartz Enterprise Job Scheduler], configured through Spring, but is made considerably simpler by Grails' convention-over-configuration approach.

A _job_ is an artefact: any class whose name ends in `Job`, placed in `grails-app/jobs`, that declares an `execute` method. The plugin discovers those classes, builds the Quartz `JobDetail` and `Trigger` objects described by their `triggers` block, and registers them with a `Scheduler` bean named `quartzScheduler`.

==== What you get

* A `Job` artefact type, with jobs auto-wired by name like any other Spring bean.
* A `triggers` DSL supporting <<quartzTriggers,simple, cron, and custom triggers>>, with multiple triggers per job.
* <<quartzDynamicScheduling,Dynamic scheduling>> — schedule, reschedule, unschedule, and fire jobs at runtime from anywhere in your application.
* A <<quartzJobManagerService,`jobManagerService`>> for inspecting, pausing, and resuming jobs and triggers.
* Optional binding of a Hibernate `Session` to each job's execution thread, so jobs can use GORM the same way a controller or service does.
* Optional JDBC job persistence for surviving restarts and for clustering.
* Optional clustering, so a schedule fires exactly once across a multi-instance deployment.

For an overview of the scheduling options available in Grails, and guidance on when to choose Quartz over Spring's `@Scheduled`, see the xref:backgroundJobs.adoc#backgroundJobs[Background Jobs] chapter.
